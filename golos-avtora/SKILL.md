# Голос автора: создание личного skill авторского стиля

**Результат этого skill: новый skill для человека** (`my-writing-style`). Он один раз сохраняется в аккаунте и дальше пишет за человека посты, статьи, продающие тексты, прогревы, воронки и лендинги:
- **как пишет сам автор**: цифры и примеры из корпусного анализа его текстов;
- **без нейрослопа**: в него вшит полный список того, чего не писать (гайд Википедии «Signs of AI writing» в русской адаптации + личный стоп-лист автора).

Сам этот skill тексты не пишет и черновики не проверяет. Он только собирает данные и создаёт личный skill.

Файлы:
- `scripts/tg_to_corpus.py`: выгрузка Telegram (HTML / JSON / zip / папка) → корпус
- `scripts/transcribe.py`: расшифровка голосовых и видео с разметкой пауз
- `scripts/style_analyzer.py`: корпусный анализ → `report.md` + `profile.json`
- `scripts/slop_check.py`: внутренний модуль анализатора, по признакам Википедии отделяет посты, написанные с ИИ, от «своего голоса»
- `references/metrics.md`: как читать каждую цифру отчёта и превращать её в правило
- `assets/personal-skill-template.md`: шаблон личного skill (с готовым разделом «Чего не писать»)

## Шаг 1. Собрать материалы

Попроси одним коротким сообщением:
1. **Выгрузку канала** с компьютера. На Windows и Linux нужен **Telegram Desktop**, на Mac **Telegram Lite** (в обычном приложении Telegram для macOS экспорта нет). С телефона выгрузку сделать нельзя. Дальше: канал → ⋮ → «Экспорт истории чата» → снять галочки с фото и видео → формат **HTML** или **JSON** → «Экспортировать». Если человек только что вошёл в Telegram на этом компьютере, Telegram может попросить подтвердить экспорт с другого устройства или подождать сутки. Прислать zip-архивом или файлы `messages*.html` / `result.json`.
2. *(По желанию)* 3–10 минут голосовых, кружков, сториз, рилсов: для разбора устной речи и сценариев видео.
3. *(По желанию)* продающие тексты, прогревы, лендинги, цепочки бота, если их нет в канале.

Нужно минимум 5 тыс. слов, хорошо 15–20 тыс. (≈100–150 постов). Если это группа или чат, а не канал, спроси имя автора, как оно отображается в Telegram (`--author`).

Где искать файлы: в Claude вложения чата обычно лежат в `/mnt/user-data/uploads/`, а если подключена папка с компьютера, перенеси файлы в рабочую среду. В Codex файлы лежат в папке, где он запущен, или там, куда укажет человек.

## Шаг 2. Среда

```bash
pip install --break-system-packages -q razdel pymorphy3 natasha beautifulsoup4
# если pip не знает флаг --break-system-packages, запусти без него
SK=<папка этого skill>   # где лежит SKILL.md
mkdir -p ~/style && cd ~/style && cp $SK/scripts/*.py .
```
Если папки `scripts/` нет (skill сохранён без файлов), напиши скрипты сам по `references/metrics.md`. Метрики должны быть те же.

## Шаг 3. Корпус

```bash
python3 tg_to_corpus.py <export.zip | папка | messages.html …> --out corpus [--author "Имя"]
```
Скрипт делит посты на повседневные и продающие, убирает дубли, сохраняет даты, реакции и медиа. Проверь вывод: посты и слова по годам, нет ли предупреждения «авторов несколько». Классификация продающих постов эвристическая: пролистай `corpus/продажи/posts.txt`, явные ошибки поправь в `posts.jsonl` (поле `register`).

## Шаг 4. Устная речь (если есть аудио или видео)

```bash
pip install --break-system-packages -q sherpa-onnx soundfile   # нужен ffmpeg
curl -sSLO https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-nemo-ctc-giga-am-russian-2024-10-24.tar.bz2
tar xjf sherpa-onnx-nemo-ctc-giga-am-russian-2024-10-24.tar.bz2
mkdir -p corpus/устное
for f in <файлы>; do python3 transcribe.py "$f" sherpa-onnx-nemo-ctc-giga-am-russian-2024-10-24 > "corpus/устное/$(basename "$f").txt"; done
```
Модель скачивается с GitHub, потому что Hugging Face в рабочей среде обычно закрыт. Паузы размечены `(.)` короче 0,7 с и `(..)` / `(...)` длиннее. Если модель не скачалась, попроси готовую расшифровку (Submagic, телефон, любой сервис) и положи её .txt в `corpus/устное/`.

## Шаг 5. Анализ

```bash
python3 style_analyzer.py corpus     # → corpus/_анализ_стиля/report.md, profile.json
```
Если долго, добавь `--no-syntax`.

## Шаг 6. Понять автора (не пропускать)

Skill по одним цифрам получается безликим. По порядку:
1. Прочитай `report.md` целиком, расшифровывая цифры по `references/metrics.md`.
2. Прочитай **сами тексты**: 5 постов с наибольшими реакциями, 5 «самых своих» и 3 «самых ИИ-шных» (раздел 14 отчёта). Отметь интонацию, юмор, темы, личные детали, отношение к читателю.
3. Если есть голосовое и пост на ту же тему, сравни их: что автор убирает из речи и во что превращает самопоправки, «вот», повторы.
4. **Длина фраз**: сравни письменную норму с устной речью и сообщениями автора. Фразы из 1–2 слов правилом не делай: в норму идёт максимум одна на пост, как акцент. Если автор говорит, что пишет длиннее, верь автору и его голосовым.
5. Опечатки (раздел 10): оставь только настоящие повторяющиеся ошибки.
6. Выпиши, какие продающие форматы у автора уже есть (анонсы, прогревы, CTA, лид-магниты) и как они устроены.

**Все нормы бери только из «своего голоса»** (раздел 14). Это посты до 30.11.2022 (до ChatGPT) плюс нижняя треть по индексу нейрослопа. Тексты, которые автор писал с ИИ, нормой не считаются: их шаблоны идут в личный стоп-лист. Если почти весь канал написан с ИИ, скажи об этом прямо и попроси добавить голосовые, переписку или старые тексты.

## Шаг 7. Собрать личный skill

Заполни `assets/personal-skill-template.md`:
- **Разделы 1–8**: цифры из отчёта и цитаты из корпуса. Каждое правило с числом и примером автора, без общих советов вроде «пишите живо».
- **Раздел 9 (форматы)**: по каждому формату структура + особенности голоса. Чего в корпусе нет (статья, воронка, лендинг), построй из ближайшего регистра автора и помечай «построено по аналогии».
- **Раздел 10.1, личный стоп-лист**: возьми из раздела 15 отчёта признаки, которые чаще всего встречаются у автора, с его же примерами и заменой в его стиле.
- **Разделы 10.2–10.7 сохрани полностью**, это общая защита от нейрослопа. Убери только то, что противоречит норме автора: если сам автор активно пользуется тире или антитезой в «своём голосе», замени запрет на его норму.
- **Раздел 11**: подставь реальные числа.
- **Вёрстку спроси у автора**: пишет он связными абзацами или короткими строками «лесенкой». Цифры переносов строк в корпусе бывают обманчивы, решает автор.
- Все `{плейсхолдеры}` заполнены, в тексте skill не осталось ни одной фигурной скобки.
- **Сам текст skill пиши без длинных тире «—»** и без шаблонов из раздела 10: модель подражает тому, как написаны её инструкции.

Затем:
1. **Пробный текст.** Напиши по новому skill один пост на тему, близкую автору, и покажи его вместе с 5–7 главными находками анализа (цифры, коротко).
2. **Сохранение.**
   - В Claude: предложи skill через `propose_skills` (name `my-writing-style`, kind `new`), чтобы человек сохранил его в один клик. Если инструмента нет, упакуй папку `my-writing-style/` с `SKILL.md` в zip, отдай файлом и объясни: Customize → Skills → «+» → Create skill → Upload a skill.
   - В Codex: сохрани файл в `~/.codex/skills/my-writing-style/SKILL.md` (Windows: `%USERPROFILE%\.codex\skills\my-writing-style\SKILL.md`) и попроси перезапустить Codex.
3. **Отчёт.** Отправь `report.md` файлом, если человек хочет детали.
4. Напомни: через 2–3 месяца с новой выгрузкой профиль можно пересчитать и обновить skill.
